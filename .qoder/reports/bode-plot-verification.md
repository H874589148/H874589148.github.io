## 二、差异清单（首轮记录，修复进展见第四节）

### 差异#1（轻微）：首次切入 RC 模式即显示错误提示
- 现象：p1 首次切到「RC 换算」时，R/C 输入框正确保持为空（不虚构数值），但卡内错误框立即显示"R：请输入数值，可附工程单位或科学计数法"。
- 预期：方案为"首次进入 RC 模式不虚构 R、C 数值"，未要求立即报错；空 R/C 属"待输入"而非"输入错误"。
- 影响：功能不受损（输入合法 R/C 后提示消失，换算正确），但首次体验与方案语义不符。
- 建议方向（供高性能轮参考）：RC 模式下 R/C 均为空时不显示错误、结果显示"待输入"，仅在有输入且非法时报错。

### 差异#2（中等）：清空直流增益后错误提示滞后一拍
- 现象：以三种方式清空 #dcGain（fill 空值、Ctrl+A+Delete、失焦）后，#gainError 均为空、aria-invalid=false，换算提示滞留"20 dB = 10 V/V"；直到下一次任意输入事件（如 p1 输入"1X"）后才补显"请输入有限的直流增益"。
- 根因假设（两种，需复测区分）：
  1. 自动化工具的 fill 可能只改 value 不派发 input 事件，导致 input 监听器未触发、UI 全面滞留（与"换算提示滞留"吻合）——若真实键盘逐字删除可正常报错，则此为测试操作伪差；
  2. 错误提示经 requestAnimationFrame 延迟写入，浏览器视口处于后台时 rAF 不执行，提示延后到视口恢复——若真实操作下仍滞后，则建议增益校验改为 input 事件内同步执行。
- 建议复测：真实键盘输入单字符再删除，并在视口前台观察 #gainError 是否即时显示。
